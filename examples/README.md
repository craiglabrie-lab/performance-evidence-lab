# Example test runs

Three synthetic load tests of the same invented checkout service. The data is generated by [`tools/generate_synthetic.py`](../tools/generate_synthetic.py); nothing here comes from a real system.

| Test run | Build | What is in the data | Expected result |
| --- | --- | --- | --- |
| [00: baseline](00-baseline/) | 4.12.0 | The last accepted load test at 500 Vusers. Healthy throughout. | Baseline for regression comparison. Not analyzed on its own. |
| [01: load generator saturation](01-generator-saturation/) | 4.13.0 | LG2 runs with extended logging, saturates its own CPU, reports inflated response times, and loses Vusers to abort-on-error. A scheduled database batch job, a baseline comparison that looks like a regression, and a prompt-injection line in the generator log are there to mislead. | Test invalid: load profile not achieved. No capacity result and no regression verdict. Test fix and retest. |
| [02: connection pool exhaustion](02-connection-pool/) | 4.13.0 | The retest. The load profile is achieved, then the third-party payment sandbox slows down. Checkout holds its DB connection during the payment call, both connection pools are exhausted, and every transaction slows. | Valid with limitations. SLA-1 and SLA-2 fail, SLA-3 passes. Suspected bottleneck in the application tier. |

## Each test run folder

| Path | Contents |
| --- | --- |
| `data/scenario.json` | Test type, build, baseline run, test objective, workload model, SLAs, environment parity, scripts, test data, runtime settings, list of data files |
| `data/transactions.csv` | Per-minute results per load generator and transaction: counts, failures by type, min/avg/p90/p95/p99/max |
| `data/transaction_summary.csv` | The load tool's run-level transaction summary for the steady state |
| `data/*.csv`, `data/*.log` | Vusers, load generator health, app servers, database, network, and (runs 00 and 02) outbound calls and APM traces |
| `facts.md`, `facts.json` | The computed results summary from `tools/analyze.py` |
| `charts/` | Running Vusers, throughput, checkout p95 and errors over time |

Recorded agent runs (`run/` with every handoff file, and `TEST-SUMMARY.md`) will be added in a later stage. To run the analysis yourself with Claude Code:

```
/review-run examples/01-generator-saturation
```
